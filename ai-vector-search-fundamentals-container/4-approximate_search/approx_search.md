# Approximate Similarity Search with Container-Generated Vectors

## Introduction

In the previous lab, you used vectors generated by the Private AI Services Container to run exhaustive similarity searches. Exhaustive search compares the query vector with every candidate vector. That produces exact results, but the work grows with the number of rows.

In this lab, you will create an In-Memory Neighbor Graph vector index and use it for approximate nearest-neighbor searches. The embedding runtime does not change: the Private AI Services Container still generates the query vector, and Oracle AI Database performs the indexed similarity search.

Estimated Time: 15 minutes

### About Approximate Similarity Search

Oracle AI Vector Search supports several vector index organizations:

* **In-Memory Neighbor Graph** uses a Hierarchical Navigable Small World (HNSW) graph. It is designed for low-latency searches when the index fits in the Vector Pool.
* **Neighbor Partition** uses Inverted File Flat (IVF) partitions. It supports larger datasets and transactional workloads when an in-memory graph is not the best fit.
* **Hybrid Vector Index** combines Oracle Text information retrieval with semantic vector search.

This lab uses HNSW because the National Parks dataset is small and fits comfortably in memory. The vectors stored in `PARKS.DESC_VECTOR` and the query vectors generated by `all-minilm-l12-v2` both have 384 dimensions.

### Objectives

In this lab, you will:

* Inspect the Vector Pool
* Create an HNSW index on `PARKS.DESC_VECTOR`
* Inspect vector index metadata and memory use
* Reuse container-generated query vectors in approximate searches
* Confirm that Oracle AI Database uses the HNSW index

### Prerequisites

This lab assumes you have:

## Task 1: View the Vector Pool

HNSW indexes are stored in the Vector Pool, a memory area allocated from the System Global Area (SGA). Autonomous AI Database Serverless allocates this memory as vector indexes are created.

1. Display the current Vector Pool allocation.

    ```sql
    <copy>
    SELECT *
    FROM v$vector_memory_pool;
    </copy>
    ```

    Before the first HNSW index is created, the output may show that little or no Vector Pool memory is in use.

## Task 2: Create an HNSW Vector Index

1. Create an HNSW index on the park description vectors.

    ```sql
    <copy>
    CREATE VECTOR INDEX parks_hnsw_idx ON parks (desc_vector)
    ORGANIZATION INMEMORY NEIGHBOR GRAPH
    DISTANCE COSINE
    WITH TARGET ACCURACY 95;
    </copy>
    ```

    `DISTANCE COSINE` matches the metric used in the workshop searches. `TARGET ACCURACY 95` asks the index to balance search speed with a target recall of 95 percent.

2. Display information about the index.

    ```sql
    <copy>
    SELECT owner, index_name, index_organization, num_vectors
    FROM v$vector_index
    WHERE index_name = 'PARKS_HNSW_IDX';
    </copy>
    ```

    The vector count should match the rows in `PARKS` that contain a description vector.

3. Display the Vector Pool allocation again.

    ```sql
    <copy>
    SELECT *
    FROM v$vector_memory_pool;
    </copy>
    ```

    The allocation and usage columns now reflect the memory consumed by the HNSW index.

## Task 3: Run Approximate Similarity Searches

The previous lab generated each remote embedding once and stored it in `PRIVATE_AI_QUERY_VECTORS`. Reusing those vectors keeps the similarity query focused on database work and avoids repeating an HTTP call while Oracle evaluates the result set.

1. Find parks related to the Civil War with an approximate search.

    ```sql
    <copy>
    SELECT p.name,
           p.city,
           p.states,
           p.description,
           VECTOR_DISTANCE(p.desc_vector, q.query_vector, COSINE) AS distance
    FROM parks p
    CROSS JOIN private_ai_query_vectors q
    WHERE q.query_name = 'CIVIL_WAR'
    ORDER BY distance
    FETCH APPROX FIRST 10 ROWS ONLY;
    </copy>
    ```

    `FETCH APPROX` allows the optimizer to use an eligible vector index. By contrast, `FETCH EXACT` forces an exhaustive comparison.

2. Run the same type of search for rock climbing.

    ```sql
    <copy>
    SELECT p.name,
           p.city,
           p.states,
           p.description,
           VECTOR_DISTANCE(p.desc_vector, q.query_vector, COSINE) AS distance
    FROM parks p
    CROSS JOIN private_ai_query_vectors q
    WHERE q.query_name = 'ROCK_CLIMBING'
    ORDER BY distance
    FETCH APPROX FIRST 10 ROWS ONLY;
    </copy>
    ```

    On this small dataset, the approximate and exact result sets may be identical. The performance benefit becomes more significant as the number of vectors grows.

## Task 4: Confirm Index Use

1. Select the following statement in the SQL Worksheet, then select **Explain Plan** and **Advanced View**.

    ```sql
    <copy>
    SELECT p.name,
           p.city,
           p.states,
           p.description
    FROM parks p
    CROSS JOIN private_ai_query_vectors q
    WHERE q.query_name = 'ROCK_CLIMBING'
    ORDER BY VECTOR_DISTANCE(p.desc_vector, q.query_vector, COSINE)
    FETCH APPROX FIRST 10 ROWS ONLY;
    </copy>
    ```

    Look for a vector index operation such as `VECTOR INDEX HNSW SCAN` on `PARKS_HNSW_IDX`. The exact presentation can vary by database release and optimizer decisions.
